# Krane's Item Tweaks & Additions server (ItemTweaks4Server)

**Requires:** SPT 4.1.6 server, WTT-ServerCommonLib `^3.0.0` (hard dependency: the server refuses to load this mod without it). Soft dependencies: WTT-Armory (source of the AEK-971 / AEK-973, the MSR, the Sabre-5 and the .300 WM FMJ; without it only the clones of these are skipped with a log line, no `ModDependencies` entry), ISB-Aishi (K.E.T.A. uses its KTE stim model, and it adds the black Modified MCX-SPEAR upper receiver sold at NATO Quartermaster and the XM1184 AP ammo put on the flea; without it these are skipped with a log line), Michael-NATOQuartermaster (its offers are skipped with a log line when absent), the client plugin ItemTweaks (applies the weight reduction of the two cases, the PS-321 view changes and the colors of the med clones; without it the cases work but their contents keep their weight, the PS-321 looks like a PS-320 and the med clones look like their sources), acidphantasm-progressivebotsystem (its tier pools are skipped when absent). WTT-Artem and More Cases Updated (their unsellable items are put on the flea; each item is skipped with a log line when absent). Fika 2.4.6 is unaffected. Clients need the ItemTweaks plugin (soft: only for the case weight cut, the case looks, the PS-321 view, the med clone colors, the Redline dossier look and the K.E.T.A. ??????? stats; without it the items still work).

## What
Adds modified clones of existing items, plus new items that reuse an existing model (the spec-ops kit case, the spec-ops key case, the Redline dossier, K.E.T.A.; below), extra trader offers of other mods' items and a flea unblock. Weapon, magazine and scope clones (variants) keep the source's model, icon, description and slots, cost 2x the source in the handbook and on the flea, and are added to every quest condition, bot pool and mastery entry that lists the source (scanned at runtime, not hard-coded). The med clones and the Redline dossier share only the source's filters; the new items have their own names, descriptions and grids.

NATO Quartermaster's own offers (everything it builds itself, not the offers added here) get unlimited stock: only its per-restock buy limits (its `*BuyLimit` config keys) cap purchases. Its stock config keys no longer matter. Skipped with a log line when the trader is absent.

**Ammo purchase limits**: every trader's single-round ammo offers (vanilla and modded traders, Fence excepted) get their per-restock purchase limit (`BuyRestrictionMax`) doubled until it is over 600 for penetration 40+ ammo and over 1000 for other ammo (e.g. 60 -> 960, 1000 -> 2000). Prices are unchanged. A finite stock below the new limit is raised to it. Offers without a limit, ammo packs, grenades, flares, the Zvezda flashbang and the 20x1mm disk are left alone. Runs after every trader is registered and after SVM's `CurrencyRestrictions` / `BarterRestrictions` multipliers, so it doubles their result. Not configurable.

## Why
Stronger, rarer variants that still count for the source's quests and mastery.

## How
Items, presets and prices via WTT item JSON (clones of the sources): `db/CustomItems` (SR-25, X-47, PS-321, spec-ops kit case, Redline dossier; names and descriptions are in each file's `locales`), `db/KeyCase` (spec-ops key case, own directory so a missing Gingy keychain cannot block the shared one), `db/Aek973`, `db/Aek971`, `db/MsrX` (MSR-X, Sabre-5-X, .300 WM CBJ; all from WTT-Armory, so skipped together), `db/Meds` (Propital-X, Adrenaline-X, Zagustin-X, SJ6-X, Nightfall), `db/Keta` (passed to WTT only when ISB-Aishi's `Aishi.ModMetadata` type is loaded: the source is vanilla, but the model is ISB-Aishi's bundle). Buffs in `db/CustomBuffs`, created before the items. WTT loads a directory recursively and logs an error per failing item, so each optional-source clone has its own directory, passed to WTT only when its source item exists. Clone definitions (ids, prices, traders, assort ids, barters) are one list in `ItemDefs.cs`; extra offers of existing items (not clones) are a second list there (`ItemOffers`). Two `IOnLoad` classes: items (Preload + 10, after WTT-Armory at Preload + 2) and quests / bots / filters / special slots / secure containers / traders / flea unblocks (TraderRegistration + 10, after NATO Quartermaster built its assort at +2, before trader/flea/preset callbacks).
Special slots are filled by our own code, not WTT's `addtoSpecialSlots`: that option only knows two fixed pockets and adds to every slot of them (not just SpecialSlot*), at Preload + 10 before other mods' pockets exist.
Trader offers use an unlimited-stock root with a purchase limit: SPT 4.1.6 does not restore decremented stock on restock but does reset each profile's purchase counts, so the limit refills every restock.

## Build and deploy
Build with `nix shell nixpkgs#dotnet-sdk_10 -c dotnet build -c Release` in `ItemTweaks4Server/`, then `scripts/deploy-server-mod.sh ItemTweaks4Server` and `scripts/restart-all.sh`. This project was renamed from ModWeapons: remove the old remote directory `krane-ModWeapons` (the server would otherwise load both).

## Settings
None. Prices and stats are in `db/**/*.json` (flea/handbook/stats, buffs in `db/CustomBuffs`) and `ItemDefs.cs` (trader prices, limits, levels).
